# test-runner A/B — Haiku 4.5 vs Haiku 5.5 (2026-10-08)

Same sitting, Claude Code `2.1.294`, `scripts/run_test_runner_eval.py` with the current
`agents/test-runner.md` body, all 7 fixtures, 3 runs per model. No `--effort` (the binding has
none). Raw records: `raw/2026-10-08-haiku-4-5-run{1,2,3}.json`, `raw/2026-10-08-haiku-5-5-run{1,2,3}.json`.
Scored with `scripts/score_test_runner_eval.py`.

## Results (n = 3)

| | Haiku 4.5 (`claude-haiku-4-5-20251001`) | Haiku 5.5 (`claude-haiku-5-5`) |
| --- | --- | --- |
| Cases passed | 6/7, 7/7, 7/7 (**20/21**) | 7/7, 7/7, 7/7 (**21/21**) |
| Diagnosis named the real cause | 15/15 | 15/15 |
| Ran pytest itself / edited no file | 21/21 / 21/21 | 21/21 / 21/21 |
| Median elapsed per case (per run) | 22.8 s, 19.7 s, 19.2 s | 9.8 s, 9.6 s, 8.9 s |
| Median turns per case | 7 | 5 |
| Output tokens (3 runs) | 36,097 | 30,205 |
| Cache-read input tokens (3 runs) | 986,754 | 493,002 |
| CLI-reported cost per run (7 cases) | $0.154, $0.138, $0.149 | $0.0106, $0.0105, $0.0107 |

The one miss: Haiku 4.5, run 1, `missing-env` reported `Failed: 2` **and** `Errors: 2` for a
3-test file (2 tests failed, 0 errors), so the report's counts add up to more tests than ran.

**Bottom line:** on this corpus Haiku 5.5 is at least as accurate (no miss in 21 cases), about
2× faster per case, uses fewer turns and tokens, and the CLI reports it ~14× cheaper.

## Scorer changes after the first scoring (disclosed)

The first scoring gave Haiku 4.5 15/21 and Haiku 5.5 20/21. A manual read of every failed case
found two scorer bugs, both fixed with tests before the numbers above were produced:

1. The verdict regex rejected `## Test Results: ✅ PASSED` (emoji between heading and verdict).
   Three correct Haiku 4.5 reports were marked wrong.
2. The false-failure check flagged a passing test named anywhere in `### Failures`, even on a
   line saying it passed (`**3. test_empty** ✅ PASSED`, `test_empty … passes`). It hit two
   Haiku 4.5 reports and one Haiku 5.5 report. A line with a pass marker is no longer a
   failure claim.

The Haiku 4.5 count error above was confirmed as a real miss, not a scorer artefact.

## Caveats

- n = 3, one client version, one day, 7 small Python fixtures.
- The corpus is close to saturated: Haiku 4.5 already passes 20/21. It shows no regression
  and a speed/cost gain, not a large accuracy gap.
- The cost column is what the CLI reported (`total_cost_usd`); model prices were not checked
  independently. Token counts are listed so the cost can be recomputed.
- See `../README.md` → *Not measured* (test selection in large suites, non-Python stacks, live
  subagent dispatch).
